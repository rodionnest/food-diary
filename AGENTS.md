# Инструкции для работы с проектом

## Назначение и устройство

Локальные дневники веса и питания Родиона и Анны. Основное описание и правила
внесения записей находятся в `README.md`. Общайся с пользователем на русском.

- `server.py` — Python HTTP-сервер, JSON-хранилище без внешних сервисов и зависимостей.
- `local-entry.js` — сохранённый локальный парсер с тестами; страницы его не подключают.
- `local-claude.js` — браузерная реализация `window.claude`: доступ к данным,
  чтение данных и подписки на обновления; запись из браузера отключена.
- `Дневник Родион.html`, `Дневник Анны.html` — страницы с собственными CSS и JS;
  идентификаторы дневников: `rodion` и `anna` соответственно.
- `nutrients.json` — справочник продуктов и микроэлементов.
- `fill_micro.py` — заполнение микроэлементов в существующих записях питания.
- `export_static.py`, `encrypt-snapshot.cjs` — экспорт и шифрование снимка для Pages.
- `pin-gate.js`, `static-diary.js` — ввод PIN, расшифровка и чтение статического снимка.
- `docs/` — публикуемый снимок; персональные коллекции только в
  `snapshot-encrypted.js`, без открытых JSON-файлов.
- `data/<rodion|anna>/<коллекция>.json` — локальные данные; коллекции `days`,
  `products`, `suspects`. Каталог исключён из Git.

Сохраняй простую текущую архитектуру. Не добавляй фреймворк, сборщик или новые
зависимости без необходимости для задачи. Правки общих функций проверяй на обоих
дневниках, сохраняя различия их полей и интерфейсов.

## Запуск и конфигурация

```bash
./start.sh
# http://localhost:8000
```

Требуется только Python 3; установка пакетов, `.env` и API-ключи не нужны.
Альтернативный запуск: `python3 server.py --host 127.0.0.1 --port 8000`.
По умолчанию используй локальный адрес. Не возвращай внешние API, шрифты или
другие сетевые зависимости без соответствующей задачи пользователя.
Формы добавления записей в браузере нет: записи вносятся через чат в локальные JSON.
Для экспорта снимка дополнительно нужен Node.js; npm-пакеты не требуются.

## Работа с данными дневников

- Не меняй реальные записи ради проверки кода. Перед массовыми изменениями
  пользовательских данных делай резервную копию: Git их не восстанавливает.
- При внесении записей через чат редактируй нужный `data/<дневник>/days.json`.
  Ключ дня — `YYYY-MM-DD`; новые дни ставь первыми, от новых к старым.
- Сохраняй существующие поля и записи. JSON записывай в UTF-8 атомарно:
  временный файл рядом с целевым, затем `os.replace`.
- Страницы опрашивают хранилище примерно каждые 4 секунды, пока вкладка видима;
  после изменения данных перезапуск сервера не требуется.
- Не смешивай данные Анны и Родиона. Если дневник или дата записи не ясны из
  контекста, уточни их до изменения данных.

Поля дня: `weight` (кг), `train`, `trainText`, `note`. У Анны дополнительно:
`steps`, `active`, `trains`, `bodyFat`, `muscle`, `cycle`.

Каждый элемент массива `meals` содержит:

- `when`: `Утро`, `Обед`, `День`, `Ужин` или `Вечер`;
- `name`: сохраняй ранее использованное название продукта для сопоставления;
- `qty`: строка, например `120 г`, `1 шт`, `150 мл`;
- `kcal`, `p`, `f`, `c`: КБЖУ всей порции, а не на 100 г.

Если КБЖУ приходится оценивать, сообщай, что это оценка. Для нового продукта
добавляй запись в `nutrients.json`: `names`, `kcal` на 100 г и массив `per`.
Порядок значений `per` должен совпадать с `keys`; для порционных продуктов
используй `portion: true`.

После добавления приёмов пищи заполняй микроэлементы нужного дневника:

```bash
python3 fill_micro.py rodion
python3 fill_micro.py anna
# Без аргумента обрабатываются оба дневника.
```

Обычный запуск сохраняет уже заполненный `micro`. `--force` пересчитывает его:
используй только когда задача требует пересчёта существующих значений.
Для обычных продуктов коэффициент равен калориям строки, делённым на калории
справочника; для `portion: true` коэффициент равен 1. Сохраняй согласованность
расчётов и округления между скриптом и страницами.

## Личные списки продуктов

Списки Родиона находятся в `data/rodion/suspects.json` и отображаются на вкладке
«Анализ». Это JSON-объект с постоянными ключами записей. Не перезаписывай весь
список при добавлении одного пункта; сохраняй существующие ключи и поля.

Поля: `name`, `level` (`red`, `orange`, `green`, `grey`, `substance`), `order`
(начиная с 1 внутри категории), необязательные `symptom`, `evidence`, `next`.
Для сопоставления с едой: `match` и `except` (регулярные выражения без учёта
регистра), либо `flag: "wheat"` / `flag: "cocoa"`. Не приписывай продуктам
скрытые ингредиенты без данных. Формулировки пользователя сохраняй как его
наблюдения, включая знаки вопроса. Все категории по умолчанию свёрнуты.

## Обновление публичного сайта

Изменение локальных JSON не обновляет Pages автоматически. После новых записей
или списков выполни экспорт → коммит → push согласно `README.md`, если публикация
разрешена текущей задачей или сессией. В этой сессии обычное обновление снимков
согласовано; не запрашивай повторно разрешение на каждый штатный коммит и push.

- Данные и резервные копии из `data/` не добавляй в Git. Не помещай персональные
  списки в HTML, README или другие открытые исходники; они входят в шифрованный снимок.
- Используй прежний PIN, если он известен из контекста. Если неизвестен — уточни,
  не заменяй его произвольно. Не записывай PIN в код, документацию и сообщения коммитов.
- `python3 export_static.py` запрашивает PIN; для автоматизации поддерживается
  переменная окружения `DIARY_PIN`. В репозитории её значение не сохраняется.
- `nutrients.json` — открытый общий справочник; его можно коммитить отдельно.
- Экспортирует оба дневника; не меняй данные Анны ради обновления Родиона.
- Проверь JSON и длины `per`, сохранность старых записей и шифрование снимка.
  После push укажи, что Pages обновляется после сборки. Дата на сайте — `DD-MM-YY`.
- Не возвращай открытую выгрузку `snapshot-data.js` или коллекций в `docs/`.
  История `main` уже очищена; обычные обновления делай без force-push.

## Проверки изменений

Проверки парсера, HTTP-хранилища и зашифрованного экспорта находятся в `tests/`;
сборщика нет. Тестам экспорта нужен Node.js.
Выбирай проверки по изменённым файлам:

```bash
python3 -m py_compile server.py fill_micro.py export_static.py
bash -n start.sh
# Если установлен Node.js и изменён браузерный адаптер:
node --check local-claude.js
node --check local-entry.js
node --check static-diary.js
node --check pin-gate.js
node --check encrypt-snapshot.cjs
node --test tests/local-entry.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

При изменении справочника проверь корректность JSON и длину каждого `per`
относительно `keys`. Для UI проверь обе страницы через HTTP: отображение,
изменённый сценарий и ошибки консоли. Проверки записи проводи на временных
данных. Не запускай платные вызовы Claude API для обычной проверки интерфейса.

Перед правками проверяй `git status`: сохраняй чужие незакоммиченные изменения.
Не переформатируй целиком большие HTML-файлы ради локальной правки.
В итоговом сообщении укажи, что изменено, что проверено и что проверить не удалось.
