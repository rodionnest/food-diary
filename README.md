# Дневники веса — локально

Запуск без интернета, API-ключей, pip и внешней БД (нужен только Python 3):

```bash
./start.sh
# либо python3 server.py
```

Открой http://localhost:8000 (из Windows тоже — WSL пробрасывает localhost).
Страницы и шрифты не используют внешние сервисы. `.env` не нужен.
Данные лежат в `data/<anna|rodion>/<коллекция>.json` (days, products, suspects).
Папка не попадает в git — делай резервные копии сам. Если локальных записей нет, дневник пуст.

Форма добавления записей удалена. Записи вносятся через чат проекта;
локальные страницы подхватывают изменения примерно за 4 секунды.

## Публичный сайт GitHub Pages

Публичный снимок обоих дневников: https://rodionnest.github.io/food-diary/.
Он работает без Python и доступа к API, в том числе при открытии `docs/index.html`
как файла. На страницах указано время подготовки снимка (UTC), запись недоступна.
Перед просмотром главной страницы и обоих дневников запрашивается PIN-код.
Вход запоминается до закрытия вкладки. Снимок шифруется AES-256-GCM; ключ выводится из PIN через PBKDF2-SHA-256.
PIN не записывается в опубликованные скрипты. Вкладка хранит ключ до закрытия.
Для экспорта дополнительно нужен Node.js (без npm-пакетов).
Четырёхзначный PIN защищает от простого скачивания читаемых записей, но допускает
перебор. Шифрование не удаляет ранее скачанные открытые копии.
Исходное хранилище — локальная папка `data/`.

Обновление после внесения записей через чат:

```bash
python3 export_static.py  # введи PIN по запросу
git add docs
# Если менялись исходники или справочник, добавь соответствующие файлы тоже.
git commit -m "Обновить публичный снимок дневников"
git push origin main
```

Экспорт требует непустых `days.json` обоих дневников, включает коллекции
`days`, `products`, `suspects` (отсутствующие необязательные коллекции — пустые),
страницы и необходимые ресурсы. Коллекции хранятся только в шифрованном снимке;
открытый `nutrients.json` в `docs/` не копируется. `.env`, локальное окружение и
служебные файлы в снимок не копируются. Не редактируй `docs/` вручную.
В GitHub Settings → Pages выбери **Deploy from a branch**, ветку **main**,
папку **/docs**. Первичная публикация требует доступа к репозиторию GitHub.

## Как добавлять записи через чат

Записи добавляются через чат Codex. Агент пишет их прямо в `data/<rodion|anna>/days.json`, ключ дня — дата в формате `YYYY-MM-DD`. Открытые страницы подхватывают изменения примерно за 4 секунды, перезапускать сервер не нужно.

1. **Вес, тренировка, заметка** — поля дня: `weight` (кг), `train`, `trainText`, `note`. Для Анны ещё `steps`, `active`, `trains`, `bodyFat`, `muscle`, `cycle`.
2. **Приёмы пищи** — массив `meals`, у каждого элемента поля:
   - `when` — один из: `Утро`, `Обед`, `День`, `Ужин`, `Вечер`;
   - `name` — название продукта; если продукт уже встречался в дневнике, название берётся такое же, как раньше (страница и `fill_micro.py` сопоставляют по нему);
   - `qty` — количество строкой, например `"120 г"`, `"1 шт"`, `"150 мл"`; страница берёт граммы из `N г` или `N мл`;
   - `kcal`, `p`, `f`, `c` — калории, белки, жиры, углеводы на всю порцию (не на 100 г).
3. **Микроэлементы** — после добавления приёмов запусти:
   ```
   python3 fill_micro.py            # оба дневника
   python3 fill_micro.py rodion     # только один
   ```
   Скрипт берёт значения из `nutrients.json` и пересчитывает их по калориям строки. Строки, где `micro` уже есть, не трогаются; `--force` пересчитывает все.
4. **Новый продукт** — если его нет в `nutrients.json`, сначала добавь запись `{"names": [...], "kcal": <на 100 г>, "per": [...]}`. Порядок чисел в `per` — как в `keys` этого же файла. Если продукт порционный (кофе, чай), ставь `"portion": true`.
5. Запись нового дня ставится первой в файле (дни идут от новых к старым). Файл пишется атомарно: сначала во временный файл, потом замена, чтобы сервер не прочитал обрезанный JSON.

Пример: `Курица жареная без кожи`, 417 г — 771 ккал, 115 г белка, 33 г жира, 0 углеводов (ккал = 185 на 100 г × 4,17). КБЖУ для продукта агент оценивает и помечает как оценку, если в дневнике или справочнике его ещё нет.
